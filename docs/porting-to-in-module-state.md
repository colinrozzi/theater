# Porting an actor to in-module state

**Audience:** actor authors migrating an existing actor onto the current Theater
runtime (the fleet transition wave). This is the *how-to*; `docs/in-module-state.md`
is the *why* + the runtime mechanism.

> **This is a hard prerequisite, not a nicety.** The runtime no longer threads
> state through calls. An actor still written the old way — state as the first
> argument and first return of every export — **will not run** on the current
> runtime (its export signatures no longer match what the runtime calls). Porting
> to in-module state is part of the one-commit per-actor rework, alongside
> `wit→pact`, `runtime→self`, and the `packr-guest 0.24` bump.

## The mental model (one paragraph)

The **chain** — the hash-linked log of each export's inputs and outputs (and the
host calls in between) — is the single source of truth. **State is a private,
in-module value that is a replayable projection of that chain.** The runtime
never holds, serializes, or threads your state; it only passes an export its own
arguments and takes back its own return. On restart/replay, the runtime re-runs
the recorded calls and your state rebuilds itself deterministically — so a crash
restarts clean. Your job as an author: keep state in a module-global cell, seed
it in `init`, and mutate it in place from your exports.

## Before → after

**Old (state-threaded) — will NOT run anymore:**
```rust
// state came in as the first arg and went back as the first return
#[export(name = "theater:simple/counter.increment")]
fn increment(state: Value /* the actor state */) -> (Value /* new state */, Value /* result */) {
    let mut count = decode_count(&state);
    count += 1;
    (encode_count(count), Value::S32(count))   // return new state + result
}
```

**New (in-module state):**
```rust
use theater_guest::State;

#[derive(Clone, GraphValue, State)]
struct CounterState { count: i32 }

#[export(name = "theater:simple/counter.increment")]
fn increment() -> Value {                       // own args only, own result only
    let new = CounterState::with_mut(|s| { s.count += 1; s.count });
    ok_result(Value::S32(new))                  // just the result; no state
}
```

State disappears from the call surface entirely. The canonical worked example is
[`test-actors/state-test`](../test-actors/state-test/src/lib.rs) — read it start to
finish; it's ~90 lines and shows every piece below.

## Step by step

1. **Depend on `theater-guest`** (it re-exports `packr-guest`) and
   `use theater_guest::State;`.

2. **Define your state type** and derive the trio:
   ```rust
   #[derive(Clone, GraphValue, State)]
   struct ActorState { /* your fields */ }
   ```
   - `State` generates a module-global cell + the `set`/`with`/`with_mut`
     accessors **and** a `theater:simple/actor.get-state` export (so the actor
     stays inspectable via `get-actor-state`).
   - `GraphValue` lets `get-state` serialize it; `Clone` is required by the derive.
   - **Non-serializable state** (host handles, resources, sockets) → don't derive
     `State`; use `theater_guest::StateCell<T>` directly and simply never expose a
     `get-state`. (Note: such state is *not* reconstructable by replay — see
     caveats.)

3. **Declare the exports in `pact_types!`**, including the auto-generated one so
   `has_export` finds it:
   ```
   exports {
       theater:simple/actor.init: func(config: value) -> result<_, string>,
       theater:simple/actor.get-state: func() -> value,   // auto-generated by #[derive(State)]
       // …your own exports, now with NO state param/return…
   }
   ```

4. **Seed state in `init`** (set the cell exactly once) and return only your own
   result — no state:
   ```rust
   #[export(name = "theater:simple/actor.init")]
   fn init(config: Value) -> Value {
       ActorState::set(ActorState::from_config(&config));
       ok_unit()  // result<_, string>::ok(())
   }
   ```
   `init` runs before any other export; reading an **unset** cell panics (an honest
   trap), so always `set` in `init`.

5. **Read / mutate in your exports** via the accessors, and drop the state
   param + state return:
   - read: `let x = ActorState::with(|s| s.field);`
   - mutate: `ActorState::with_mut(|s| { s.field = …; });`

6. **Rebuild + recompose** with `packr-guest 0.24`, fold in the wit→pact and
   runtime→self changes, and run your scenario suite. On the new runtime a state
   mismatch fails **at spawn** (`MissingInterfaceMetadata` / signature mismatch),
   not at test time — so if it spawns and your calls round-trip, you're on the new
   model.

## Caveats (the replay contract)

- **State must be a deterministic function of the chain.** `init(config)` + the
  sequence of export calls + the recorded results of host calls must fully
  determine your state. Don't derive state from anything the chain doesn't
  capture. (Time/randomness obtained *via host calls* are fine — those are
  recorded and replayed; ambient non-deterministic sources are not.)
- **Anything in a `StateCell` you don't expose via `get-state` is not
  replay-reconstructable.** That's the right tool for genuinely non-serializable
  handles, but understand it won't survive a cold rebuild — only live restart with
  a warm module.
- **One `#[derive(State)]` per module.** Compose all your actor state into one
  type.
